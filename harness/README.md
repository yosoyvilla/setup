# harness

Single source of truth for AI coding-agent configuration on this workstation.
Claude Code, opencode and Codex all receive **generated** copies — never edit a tool's own
directory; every generated file carries a `GENERATED by ~/.harness/sync.py - DO NOT EDIT` banner.

## Use
```
python3 ~/.harness/sync.py --dry-run   # preview
python3 ~/.harness/sync.py             # apply (idempotent: a second run reports only "same")
```

## Layout
| path | contents |
|---|---|
| `agents/*.json` | canonical, tool-agnostic agent definitions + per-tool frontmatter overrides |
| `skills/` | skills, copied verbatim (binary assets included — sync copies bytes) |
| `rules/`, `hooks/` | shared rules and enforcement hooks |
| `instructions/` | `CLAUDE.md` (Claude Code) and `AGENTS.md` (opencode, and `~/AGENTS.md`) |

## Why the generator, not symlinks
Per-tool schemas genuinely differ and a wrong shape breaks the tool:
Claude uses `tools: A, B` + `model: sonnet`; opencode uses a `permission:` map and NaN model ids;
Codex uses `.toml`. Emitting Claude's shape into opencode fails with
`Expected object | undefined, got "..." tools`.

## Hooks
Added because measurement showed prose rules do not hold: on a 10-probe compliance suite
(6 runs/arm, claude-sonnet-5) every hook-backed rule scored 6/6 while prose-only rules failed.
Overall 47/60 -> 57/60 (p=0.0136); live re-run after cutover 29/30.

- `md-approval-guard.sh` — PreToolUse(Write|Edit|MultiEdit): asks before creating a NEW `.md`.
  The prose rule alone measured **0/6**; with the hook, 6/6.
- `force-push-guard.sh` — PreToolUse(Bash): denies force-push without `--force-with-lease`.
  Scoped to the flags belonging to the `push` itself; 15-case offline suite in
  `hooks/test-force-push-guard.sh`.
- `verify-after-edit.sh` — Stop: blocks once when files changed but no command ran afterwards.
